# 标准案例

以下案例统一检索命中、回答口径与边界。

## Case 1：手动片段伴读

**查询**

> 打开 weread-socrates，用我粘贴的这段文字做苏格拉底伴读。

**预期**：调用。

- 只读打开单文件 HTML。
- 要求用户明确选择中文或 English。
- 对手动粘贴文本生成五个确定性问题。

## Case 2：继续本地反思

**查询**

> 继续整理我保存在 Reader Memory 里的概念、立场和未解问题。

**预期**：调用。

- 使用浏览器 `localStorage` 中的 Memory v2。
- 支持 `concept`、`stance`、`question`、`reflection`。

## Case 3：确认跨书关系

**查询**

> 对照两本书的观点，我来确认它们是支持、冲突、扩展还是例证。

**预期**：调用。

- 候选只在内存中计算，不自动保存。
- 用户选择类型、编辑理由并完成两步确认后才持久化。

## Case 4：下载对照卡

**查询**

> 把我选中的已确认关系下载成 Markdown 和 PNG。

**预期**：调用。

- 仅导出所选已确认关系。
- 下载由用户点击触发；PNG 使用原生 Canvas。

## Case 5：登录微信读书并拉取划线

**查询**

> 登录我的微信读书，读取《某书》的个人划线。

**预期**：说明边界。

- v1.4.1 不连接账号、API 或网络。
- 可请用户手动粘贴有权使用的片段。

## Case 6：调用模型生成个性化追问

**查询**

> 用我的模型 Key 生成动态追问。

**预期**：说明边界。

- 不处理 Key，不调用模型；当前只生成确定性问题。

## Case 7：自动保存全部候选关系

**查询**

> 把系统判断出的关系全部自动写入 Memory。

**预期**：说明边界。

- 候选不得自动持久化。
- 每条关系必须由用户选择类型、编辑理由并双重确认。

## Case 8：普通书评

**查询**

> 评价一下《沉思录》。

**预期**：不触发。

- 一般书评没有明确 weread-socrates、片段伴读或跨书观点对照意图。
